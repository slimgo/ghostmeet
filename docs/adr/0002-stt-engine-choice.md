# WhisperKit — основной STT, нативный SpeechAnalyzer — только для английского

status: часть про «нативный `SpeechAnalyzer` применим только к англоязычным звонкам» **заменена** [ADR-0013](0013-native-recogniser-knows-russian-but-loses-the-terms.md): русский у нативного пути есть — через `DictationTranscriber`, а не `SpeechTranscriber`, — но термины он теряет. Остальное живо.

Основной движок распознавания — **WhisperKit** (пакет [`argmaxinc/argmax-oss-swift`](https://github.com/argmaxinc/argmax-oss-swift), CoreML/ANE, подключён версией 1.0.0) с выбором модели в настройках. Нативный `SpeechAnalyzer` из macOS 26 подключается вторым движком и применим только к англоязычным звонкам.

Причина — проверяемый факт, а не предпочтение: `SpeechTranscriber` на macOS 26.5 отдаёт **30 локалей, среди которых нет ни одной кириллической**. Русского нет, и докачкой языковых ассетов это не лечится. При этом по остальным характеристикам нативный путь выигрывает у Whisper: вдвое быстрее `large-v3-turbo`, VAD (`SpeechDetector`) в комплекте, ноль зависимостей и ноль скачиваемых моделей — поэтому для английского его стоит использовать, а не игнорировать.

Проверить актуальность утверждения можно так:

```swift
let supported = await SpeechTranscriber.supportedLocales
print(supported.map { $0.identifier(.bcp47) }.sorted())
```

## Consequences

- MLX как рантайм для Whisper из спеки **отклонён**: под Swift экосистема сырая, а WhisperKit закрывает ту же задачу зрелым кодом на ANE. Спека в этой части устарела.
- Минимальная версия macOS остаётся **14.4**, а не поднимается до 26: нативный движок опционален и закрыт `@available`.
- Старый `SFSpeechRecognizer` русский поддерживает, поэтому остаётся как аварийный запасной путь — но именно для русского, а не «вообще».
- Выбор модели Whisper — пользовательская настройка, значит нужен и UI загрузки моделей, и обработка состояния «модель ещё качается».
