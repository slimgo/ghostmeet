# Приложение спрашивает о новой версии при старте

**status:** заменён в части — фраза «Оно не вводит автоматического обновления и не приближает его» отменена [ADR-0012](0012-sparkle-installs-the-update.md); остальное живо.

Раз при запуске GhostMeet делает **один** запрос к GitHub — за номером последней опубликованной версии — и, если она новее установленной, показывает об этом одну строку в своём окне. Проверка включена по умолчанию и выключается одним переключателем в настройках; выключенная, она не делает запроса вовсе.

Это первое обращение приложения наружу, которого пользователь не просил. До сих пор в сеть уходило только то, что он инициировал сам: запрос к провайдеру по нажатию аккорда и разбор резюме по нажатию кнопки. Поэтому решение записывается, а не просто делается.

Причина в способе доставки. У приложения нет ни магазина, ни встроенного обновления: оно раздаётся образом, который коллега перетаскивает в «Программы» и снимает карантин руками. Узнать о новой сборке ему неоткуда — никто не рассылает писем, а заходить на страницу релизов незачем, пока всё работает. Без проверки машина остаётся на той версии, которую ей однажды дали, и остаётся там навсегда. Это уже происходило внутри проекта: образ `0.1` лежал у коллег, пока следующая правка чинила падение при старте.

Включённое по умолчанию — часть решения, а не недосмотр. Проверка, которую надо не забыть включить, не включается никогда: её увидит тот, кто и так следит за релизами, и не увидит тот, ради кого она заведена.

## Что именно уходит

IP-адрес и версия приложения в `User-Agent` — то есть ровно те два факта, о которых запрос и задан. Не уходит ничего больше: ни транскрипта, ни профиля, ни заготовок, ни идентификатора машины или пользователя. Ответ — публичная страница, которую может открыть кто угодно без ключа и без учётной записи.

Запрос идёт к `api.github.com/repos/.../releases/latest`. Именно к `latest`, а не к списку тегов: GitHub исключает из него черновики и пред-релизы, поэтому тег, выложенный одному человеку на пробу, не превращается в уведомление на чужой машине. Версии, которая не разбирается как `MAJOR.MINOR.PATCH`, для приложения не существует — беты идущему на собеседование не предлагают.

## Consequences

- **Любой сбой — это тишина.** Нет сети, кафе без интернета, лимит запросов, репозиторий без релизов, тег, который не разобрать, — всё кончается одинаково: ни строки, ни ошибки, ни записи в лог. Это самое неважное действие приложения, и права занять строку окна жалобой на себя у него нет. Системного уведомления нет по той же причине, что и у всего остального здесь: баннер всплывёт поверх шаринга ([ADR-0004](0004-invisibility-scope.md)).
- **Строка живёт только до звонка.** Она исчезает, как только включили прослушивание, и закрывается крестиком. Новая версия — это новость, а не диагноз; новость, висящая над лентой подсказок час, — та самая назойливая честность, которую перестают читать. Ровно так же ведёт себя вторая ветка `routeNotice`.
- **Закрытие не запоминается на диске.** «Скрыл» значит «не сейчас, я иду на звонок», а не «не говори мне об этой версии больше никогда», и живёт это ровно столько, сколько окно.
- **Под тестами проверка не выполняется.** Набор хостится внутри приложения, поэтому каждый `xcodebuild test` иначе клал бы запрос к GitHub на провод — шум на машине разработчика и лимит запросов на раннере, где сотни задач делят один адрес.
- **Появляется зависимость от координат репозитория в коде.** `GitHubReleaseCatalog.ghostMeet` — одно место, где записаны владелец и имя; форк, забывший его поменять, будет спрашивать про чужие релизы.
- **Приложение теперь знает свою версию.** `AppVersion.running()` читает `CFBundleShortVersionString`, то есть `MARKETING_VERSION` после подстановки. Это связывает поведение приложения со схемой версий и с `scripts/release.sh`: тег, разошедшийся с версией внутри бандла, сделает уведомление либо вечным, либо невозможным. Расхождение ловится в CI отдельным шагом.

## Чего это решение не отменяет

Оно не вводит автоматического обновления и не приближает его: приложение не скачивает образ, не проверяет его подпись и ничего не заменяет. Ссылка ведёт на страницу релиза, где написано, что изменилось, — а решение обновляться принимает человек, и во время звонка это решение почти всегда «не сейчас».

Оно не превращает GitHub в зависимость приложения: без ответа GhostMeet работает ровно так же, как работал.
