# Сохранённые звонки — материал для порогов протечки

Сюда кладутся файлы, которые приложение отдаёт по кнопке «Сохранить диалог».
По ним подбираются пороги `LeakDedup` — так же, как пороги 0.83 и 5 были
подобраны по записям расследования ADR-0009: измерением зазора между наборами,
а не на глаз.

**Всё, кроме этого README, не отслеживается git.** Так и задумано: в файлах
живая речь живых людей, а репозиторий публичный. Правило записано в
[`.gitignore`](../../.gitignore) и снимать его не нужно — работа с материалом
не требует, чтобы он лежал в истории.

## Что класть

Несколько файлов с настоящих звонков, по возможности — тех, где протечка
запомнилась: голос собеседника из динамиков приехал в канал `You` и **остался
неперечёркнутым**. Это и есть пропуски, ради которых всё затевается.

Файлы с чистых звонков тоже нужны, и не в меньшей степени. Ложное срабатывание
дороже пропуска — вычеркнутая настоящая реплика исчезает из промпта, и модель
отвечает не на то, — поэтому набор честных реплик, который новый порог обязан
не тронуть, важнее набора протечек, который он должен поймать.

## Что в этих файлах есть и чего нет

Знать это нужно до того, как из них считается первое число.

**Есть:** реплики обоих каналов текстом, время начала каждой как `мм:сс` от
первой записи, ответы модели, шапка с числом уже перечёркнутых строк.

**Нет:** текста перечёркнутых протечек — они из файла вычищены, в шапке стоит
только счётчик; и длительности реплик — сохраняется момент начала, а не отрезок.

Отсюда два следствия для работы. Пропущенные протечки видны полностью и
измеряются по-настоящему. А `LeakDedup.overlap` считает по длительностям,
которых в файле нет, — значит пересечение по времени восстанавливается
приблизительно, и всякий вывод, который держится на одном лишь пересечении,
проверяется отдельно, а не принимается на веру.

Подробности разбора — [`../leak-detection/spec.md`](../leak-detection/spec.md).
