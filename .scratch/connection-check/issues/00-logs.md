# 00 — Лог, который переживает сессию

**What to build:** поднять уровень lifecycle-строк с `info` до `notice`.

**Почему сейчас.** `Logger.info` не пишется в постоянное хранилище — оно живёт в
памяти и отбрасывается. Проверено после живого прогона: `log show --info --last 6h`
не отдал **ни одной** строки от процесса. Значит строки, заведённые ровно ради
разбора «почему не работает на чужой машине», этой задачи не решают вовсе.

`notice` (`Logger.notice`, он же default level) сохраняется и достаётся обычным
`log show`.

**Что поднять:** старт и отказ захвата (`SessionEngine`), статус канала `Them`
(`SessionController`), фаза модели (`SpeechModelStatus`). Их всего несколько на
сессию — объём не вырастет.

**Чего не делать:** ничего per-frame. Правило из CLAUDE.md в силе: per-frame лог в
этом приложении пишет разговор на диск.

**Acceptance:**
- после запуска приложения `log show --predicate 'process == "GhostMeet"' --last 1h`
  показывает строки старта;
- ни одной новой строки в горячем пути.

**Blocked by:** None.

**Status:** ready-for-agent
